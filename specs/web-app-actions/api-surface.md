# API surface contract: The local web view, delivery step 2 (Run and Stop)

> **Immutable during stage 6.** Nothing locks this file; it holds because agents hold it. An implementation that finds
> this wrong stops and returns to stage 3; it does not edit this file.

## Semver classification

**Minor (below 1.0).** Additive: new declarations in `@indaba/core` (types only), three new HTTP resources and one new
field on an existing response, one new optional option of `startServer`, one new optional dependency of `ui`, one
internal method on `RunChild`. One existing check is **tightened**: a write without an `Origin` header is refused, which
also applies to the existing settings `PUT`; the page always sends one, so no supported client changes. No existing
export, route, field or command changes meaning. `CONTRACT_VERSION` moves `1.0.0` to `1.1.0`.

## `@indaba/core` `web-contract` (types only, no runtime code, no `node:`)

```ts
/** One workflow file found in a served root. */
export interface WorkflowSummary {
  /** Opaque. The page sends it back; it is matched against a fresh scan, never opened as a path. */
  readonly id: string;
  readonly name: string;
  /** Relative to its root, forward slashes. */
  readonly path: string;
  /** The root's folder name, to tell two projects apart. */
  readonly project: string;
  readonly valid: boolean;
  /** One plain sentence per problem, as `indaba validate` words them; empty when valid. */
  readonly problems: readonly string[];
}
export interface WorkflowListResponse {
  readonly workflows: readonly WorkflowSummary[];
  /** True when the scan stopped at its limits, so the list may be incomplete. */
  readonly truncated: boolean;
}

/** What a first run will use, as the workflow file declares it. Text only; each item cut to a bounded length. */
export interface RunSummaryOfUse {
  /** The runner of every step, by name. */
  readonly runners: readonly string[];
  /** `shell` command lines, every `agent.command`, every local MCP server command. */
  readonly commands: readonly string[];
  /** One line per step; a step that declares none reads "runner default (unrestricted)". */
  readonly permissions: readonly string[];
  /** Steps that need a person (`arbiter: human`); they end escalated, because the run has no terminal. */
  readonly needsPerson: readonly string[];
}

export interface StartRunRequest {
  readonly workflowId: string;
  /** The `contentHash` of a `confirmation_required` answer, to confirm that content. */
  readonly confirmedHash?: string;
}
export interface StartRunResponse {
  /** The task id, generated by the server. Poll `GET /starts/{startId}` for the run. */
  readonly startId: string;
}
export interface ConfirmationRequired extends ApiError {
  readonly code: 'confirmation_required';
  readonly contentHash: string;
  readonly use: RunSummaryOfUse;
}

export interface StartStatusResponse {
  readonly state: 'starting' | 'running' | 'failed';
  /** The trace id, once the engine has opened the trace; what `GET /runs/{id}` takes. */
  readonly runId?: string;
  /** For `failed`: the first line of the child's error stream, redacted and sanitised. */
  readonly failure?: string;
}

export interface StopRunResponse {
  readonly state: 'stopping' | 'ended';
}
```

## `@indaba/server`

```ts
/** What the command line supplies so the server itself spawns and writes nothing. */
export interface RunControl {
  /** The workflows of the served roots; a bounded scan, fresh at every call. */
  list(): Promise<WorkflowListResponse>;
  /**
   * Starts the workflow `workflowId` names. Resolves with the start id, or rejects with a `RunControlError` whose
   * `code` is `workflow_not_found`, `workflow_invalid` (detail: problems), `confirmation_required` (detail: contentHash,
   * use), `too_many_runs`, `not_saved` or `start_failed`.
   */
  start(request: StartRunRequest): Promise<StartRunResponse>;
  /** `undefined` for an id this control never issued. */
  startStatus(startId: string): StartStatusResponse | undefined;
  /** `undefined` when this server did not start the run `runId` (a trace id). Idempotent. */
  stop(runId: string): StopRunResponse | undefined;
  /** True while a run this server started is alive. Keyed by trace id. */
  isAlive(runId: string): boolean;
  /** Cancels every child, waits at most `STOP_GRACE_MS`, kills the tree of any still alive. */
  stopAll(): Promise<void>;
}
export class RunControlError extends Error {
  constructor(readonly code: string, message: string, readonly detail?: Readonly<Record<string, unknown>>);
}
// ServerOptions gains one optional member:
//   readonly runs?: RunControl;   // without it the server stays read-only and the three resources answer 404
export const MAX_CONCURRENT_RUNS = 4; // a starting value, not a measurement
```

| Method and path | Needs | Answers |
| :--- | :--- | :--- |
| `GET /api/v1/workflows` | token | `200 WorkflowListResponse`; `404 runs_unavailable` without `runs` |
| `POST /api/v1/runs` | token, `Origin`, JSON body | `202 StartRunResponse`; `404 workflow_not_found`; `409 confirmation_required` / `not_saved`; `422 workflow_invalid`; `429 too_many_runs`; `500 start_failed` |
| `GET /api/v1/starts/{startId}` | token | `200 StartStatusResponse`; `404 start_not_found` (also for an id of the wrong shape) |
| `POST /api/v1/runs/{id}/stop` | token, `Origin` | `202 StopRunResponse` (`stopping`) while alive, `200` (`ended`) after exit; `404 run_not_found`; `409 not_started_here` |
| `GET /api/v1/runs/{id}` | token | existing answer plus `canStop` |

`methodsOf` allows `POST` for `/runs` and `/runs/{id}/stop` only when `runs` was given. Ids taken from the path are
checked with `isRunId` before use. Bodies over `MAX_BODY_BYTES` are `413`; a body that is not `application/json` is
`415`; any field of the body other than `workflowId` and `confirmedHash` is ignored. The messages of the 400, 403, 413
and 415 answers no longer say "settings".

```ts
// checks.ts
export function originAllowed(origin: string | undefined, port: number): boolean; // undefined is now false
```
`originAllowed` is called only for methods other than `GET`, so reads are unchanged.

## `indaba` (CLI)

```ts
// UiDeps gains one optional member, supplied by main.ts:
//   readonly runControl?: (roots: readonly string[]) => RunControl;
// RunChild (internal, not exported from the package) gains:
//   kill(): void;   // the process tree; a no-op once the child has exited
```

`indaba ui` help text changes: it no longer says it starts nothing, and says that closing it stops the runs it started.
No new option. No change to any other command. `kill()` ends a tree with `taskkill /PID <pid> /T /F` (argument array,
`windowsHide`) on Windows and a `SIGKILL` to the process group elsewhere; it is called only after the grace period.

## Files

- `<user config folder>/indaba/confirmed-workflows.json`: `{ "<realpath of root>": { "<relative path>": ["<sha256 hex>", ...] } }`,
  at most 10 hashes per workflow, written atomically. Outside every project.
- `<root>/.indaba/run-inputs/<startId>.yml`: the confirmed bytes, created with `wx`, deleted when the child exits, and
  swept at the start of `indaba ui`. Never scanned as a workflow. Gitignored with the rest of `.indaba/`.

## Log records (existing contract, new names)

`server.runs`: `run started` (start id, workflow path), `run stop requested`, `start refused` (code). `cli.ui`: `run ended`
(start id, exit code), `runs stopped at exit` (cancelled, killed). Never the token, a body or an environment value.

## Not changed

No engine event, span attribute, workflow field, runner, guard or plugin contract.
