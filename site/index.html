indaba (Zulu, Xhosa) · n. a gathering where a matter is talked through until it is settled.

Let your agents argue. Ship what they agree on.

Indaba is a deterministic engine for multi-agent AI workflows. It runs a graph of steps behind quality gates, seats agents in a council that cross-examines until it reaches consensus, and records every token and dollar as an OpenTelemetry trace.

Get started Read the workflow format

$ npx indaba@next validate workflow.ai.yml

01

A graph with gates

Steps run in a declared order. A guard (a command, a git diff, a file check) decides whether a step passed, and a failure retries the target step with only the last failure, never the whole history.

02

A council, not a chorus

Two or more agents review the same work and answer each other's points until they agree, or a human rules on the transcript.

03

Any runner

Agent CLIs, ACP agents, an OpenRouter model or a plain shell command behind one contract, in a git worktree when a step asks for one, with a fallback when the first transport is not there.

04

Every token counted

A run is a trace, a step a span. Tokens and cost come from the provider or are marked unknown, never invented. Follow it in the terminal or in the browser.

A workflow is one file you can read.

Roles name the runner behind each agent. Steps say what to do, who checks it, and what happens when it fails. indaba validate lists every problem at once, indaba plan shows the order, and indaba run executes it.

Every field of the format · The examples

# examples/review-debate.workflow.ai.yml
version: "1.0"
name: "review-debate"

roles:
  claude:
    runner: "claude-code"
  antigravity:
    runner: "antigravity"

steps:
  - id: "review_debate"
    role: "claude"
    consensus_with: ["antigravity"]
    decision_type: "consensus"
    arbiter: "human"
    goal: >-
      Review src/core in the working directory for correctness bugs and unclear design ...
